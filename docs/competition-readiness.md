# 汉韵镜零售导购工作流：参赛准备

定位：汉服零售企业的导购与售前客服部门。合作商家、访谈与比赛开始日期尚未提供。业务价值是待验证假设，不是已经取得的经营成果。

## 可演示流程

1. 用户填写预算、尺码、颜色和数量，输入非敏感购买需求。
2. 在线模型读取真实目录及史料，提交结构化商品选择。
3. 服务端按具体 SKU 验证总预算、库存、尺码和颜色；不符合条件的规格不进入可选列表。
4. 用户选择规格，二次确认加入衣囊。服务端再次检查价格及库存；重复请求不重复加购。
5. 无匹配或礼仪核验需求生成商家待办；用户也可主动请求协助。
6. 独立后台回复并完成待办，用户在选购记录查看回复。接待、依据和执行步骤保存到 SQL。

预算为“本款衣裳 × 数量”，不包括另选配饰或运费。加购不是成交。每次接待最多确认一个候选规格；另选衣裳时发起新接待。

## 评测

`node scripts/evaluate-retail.mjs` 仅列出30个构造用例，不调用模型。加 `--online --limit=3` 才会真实调用已配置模型并可能计费。结果保存在 `output/evaluation`；后台标记 EVALUATION，不计入接待指标。评测不加购、不下单、不修改商品。最多可指定30例，按实际额度使用。

用例覆盖预算、尺码、颜色、数量、朝代和人工协助，不能代替企业试点。保留失败样本；协议桩只用于自动化测试，不冒充真实模型效果。真实试点应补充约30～50条授权脱敏咨询，使用同批案例对比人工耗时、任务完成率、约束正确率和事实正确率。转化率和退货率需长期交易数据，现阶段不填写提升比例。
